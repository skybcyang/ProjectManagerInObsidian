# 需求与设计

> **项目目标**: 在 Obsidian 中实现一套完整的项目管理系统，支持版本、项目、特性三层结构化管理。
> 
> **当前版本**: v0.6.0

---

## 1. 核心需求

### 1.1 三层数据管理

| 层级 | 存储位置 | 核心字段 | 说明 |
|------|---------|---------|------|
| **版本** | `Versions/*.md` | id, name, status, startDate, endDate, owner, tags, trMilestones | 产品版本迭代，支持 IPD TR 里程碑 |
| **项目** | `Projects/*.md` | id, name, status, priority, versionId, owner, tags | 必须关联版本 |
| **特性** | `Features/*.md` | id, name, status, priority, versionId, projectId, dueDate, progress, owner, tags | 必须关联项目 |

**数据存储原则**:
- 元数据放在 frontmatter 中
- 详细描述、进度反馈写入正文
- 使用 `[[WikiLink]]` 建立关联

### 1.2 IPD 流程与 TR 里程碑

从 v0.6.0 开始支持完整的 IPD（集成产品开发）流程：

| TR 阶段 | 说明 | 关键交付物 | 颜色 |
|---------|------|-----------|------|
| **TR3** | 需求锁定 | 需求规格说明书、原型设计 | 🔵 #3498db |
| **TR4** | 开发完成 | 代码、单元测试、技术文档 | 🟣 #9b59b6 |
| **TR4A** | 转测完成 | 测试用例、测试报告、Bug 清单 | 🟡 #f39c12 |
| **TR5** | 质量工程 | 性能测试报告、安全审计报告 | 🟠 #e67e22 |
| **TR6** | 发布准备 | 发布说明、运维文档、培训材料 | 🟢 #27ae60 |

**TR 状态**:
| 状态 | 说明 | 图标 | 颜色 |
|------|------|------|------|
| `not-started` | 未开始 | ⏳ | text-muted |
| `in-progress` | 进行中 | 🔄 | text-accent |
| `passed` | 已通过 | ✅ | text-success |
| `blocked` | 阻塞 | ⚠️ | text-error |

**TR 检查点数据结构**:
```yaml
trMilestones:
  tr3:
    status: in-progress
    plannedDate: 2026-04-15
    actualDate: 2026-04-18
    deliverables:
      - name: 需求规格说明书
        completed: true
      - name: 原型设计
        completed: false
    risks:
      - description: 需求变更风险
        level: high
```

## 2. 数据模型

### 2.1 版本状态

| 状态 | 说明 |
|------|------|
| `planning` | 规划中 |
| `in-progress` | 进行中 |
| `completed` | 已完成 |
| `archived` | 已归档 |

### 2.2 项目/特性状态

| 状态 | 说明 |
|------|------|
| `backlog` | 待规划 |
| `todo` | 待办 |
| `in-progress` | 进行中 |
| `testing` | 测试中 |
| `completed` | 已完成 |
| `archived` | 已归档 |

### 2.3 优先级

| 优先级 | 说明 | 颜色 |
|--------|------|------|
| `critical` | 紧急 | 🔴 #ef4444 |
| `high` | 高 | 🟠 #f59e0b |
| `medium` | 中 | 🔵 #3b82f6 |
| `low` | 低 | 🟢 #22c55e |

### 2.4 分组方式

支持按以下字段分组：
- `status` - 状态
- `priority` - 优先级
- `version` - 版本
- `project` - 项目
- `dueDate` - 截止日期
- `trPhase` - TR 阶段

## 3. 视图代码块配置

### 3.1 完整配置示例

```yaml
mode: kanban              # 必需: kanban/list/cascade/timeline/timeview/roadmap
entityType: feature       # 可选: version/project/feature
title: 我的视图            # 可选: 自定义标题

# 实体筛选
version: ver-001          # 版本ID筛选
project: proj-001         # 项目ID筛选

# 或高级筛选
filters:
  - operator: and
    conditions:
      - field: status
        operator: equals
        value: in-progress
      - field: priority
        operator: in
        value: [high, critical]

# 分组
groupBy: status           # status/priority/version/project/dueDate/trPhase

# 排序
sortBy: dueDate           # name/dueDate/priority/progress/created
sortOrder: desc           # asc/desc

# 限制
limit: 20

# 列表视图列配置
listColumns:
  - name
  - status
  - priority
  - owner
  - dueDate
  - progress

# 卡片字段配置
cardFields:
  required: [name, priority]
  optional: [status, owner, dueDate, progress, tags]

# 级联视图选项
expanded: true
maxProjects: 5
maxFeaturesPerProject: 3

# 时间线方向
direction: horizontal     # horizontal/vertical/fishbone
```
