# 核心设计原则

> **文档状态**: ✅ 已更新
> **最后更新**: 2026-04-13
> **版本**: v0.7.3

---

## 概述

本文档定义 Project Manager for Obsidian 插件在架构、数据模型和交互层面的核心设计原则。

**v2.0 核心变更**: 
- 所有界面都在 Markdown 文件中进行，总览页面作为统一入口
- **双层架构**: Core (文件系统层) + UI (看板卡片层)

---

## 1. 总览页面中心原则（Dashboard as Entry）

> 所有操作通过 `ProjectManager/总览.md` 页面进行，不再使用独立的 Custom View。

### 说明

- 侧边栏按钮只负责打开总览页面
- 总览页面是一个普通的 Markdown 文件，包含：
  - 快速操作按钮（通过 post-processor 实现）
  - 特性看板（通过 `pm-view` 代码块实现）
  - 统计信息（通过 Dataview 代码块实现）
- 用户可以自定义总览页面内容

### 收益

- 完全符合"文件即真相"原则
- 用户可以自由编辑总览页面布局
- 支持 Obsidian 原生功能（链接、标签、搜索等）

---

## 2. 双层架构原则（Two-Layer Architecture）

> 将插件拆分为清晰的 Core 层（数据）和 UI 层（展示）。

### Core 层职责

- **FileSystem**: 所有文件操作的唯一入口
- **EntityCache**: 内存缓存层，监听文件变更自动更新
- **Entity Stores**: 每个实体（Version/Project/Feature）独立管理
- **EntityManager**: 对外暴露的唯一接口，协调各 Store

### UI 层职责 (v0.7.3)

- **ViewEngine**: 视图引擎主类，统一处理所有视图渲染
- **RendererRegistry**: 渲染器注册表，管理 8 种视图渲染器
- **Controllers**: 控制器层（ToolbarController, SortMenuController, PropertyPanelController）
- **FilterBar**: 统一筛选栏，支持实体类型/层级/属性筛选
- **EntityStrategy**: 实体策略模式，统一封装不同实体类型的操作

### 收益

- **职责清晰**: 数据与展示分离
- **可测试性**: Core 可独立测试，UI 可 mock 数据
- **可扩展性**: 新增实体 = 新增 Store + 新增 Card

## 3. 渐进式复杂度原则（Progressive Complexity）

> 用户可以从只用一个层级开始，需要时再启用多层。

### 说明

v2.0 调整为**三层强依赖结构**：
- **版本** 是顶层，必须存在至少一个版本
- **项目** 必须关联版本
- **特性** 必须关联项目和版本

但支持创建"默认版本"来降低入门门槛。

### 收益

- 数据结构清晰，避免孤儿数据
- 支持复杂的版本规划和进度跟踪

---

## 4. 文件即真相原则（File is the Source of Truth）

> 任何数据都应该能在关闭插件后，通过阅读 Markdown 文件本身被理解。

### 说明

- 版本、项目、特性都是独立的 Markdown 文件
- frontmatter 存储元数据
- 正文存储详细描述
- **总览页面也是 Markdown 文件**

### 实践建议

- 限制 frontmatter 字段数量
- 禁止将运行时状态写入 frontmatter
- 总览页面的按钮使用 post-processor 动态渲染

---

## 5. Obsidian 原生能力优先原则（Native First）

> 能用 Obsidian 原生功能解决的，就不自己造轮子。

### 说明

- 看板使用 code block processor（`pm-view`）
- 按钮使用 markdown post-processor
- 统计使用 Dataview（用户可选安装）
- 不使用 Custom View

### 实践建议

- 用 `[[WikiLink]]` 建立关联
- 用 Obsidian 标签系统补充分类
- 利用 Dataview 实现复杂查询

---

## 6. 弱引用与容错原则（Weak References & Graceful Degradation）

> 允许链接断裂，系统不应因一个文件被手动删除或重命名而崩溃。

### 说明

- 删除版本时，检查是否有关联项目
- 删除项目时，关联特性的 projectId 置空
- 渲染时检查文件是否存在，不存在显示"未找到"

---

## 7. 视图与数据分离原则（View ≠ Data）

> 看板是视图层，Markdown 文件是数据层。

### 说明

- `pm-view` 代码块是只读视图，但**卡片可点击跳转**
- 状态变更通过编辑文件或使用命令完成
- 总览页面布局不影响数据

---

## 原则优先级

当两条原则发生冲突时，按以下优先级决策：

1. **文件即真相原则** — 不可妥协
2. **总览页面中心原则** — v2.0 核心设计
3. **双层架构原则** — 代码组织基础
4. **Obsidian 原生能力优先原则** — 优先复用
5. **弱引用与容错原则** — 保障稳定性
6. **渐进式复杂度原则** — 影响用户体验
