## 3. 核心流程

### 3.1 创建实体

```
User Input
    ↓
Validation (Modal 层)
    ↓
EntityManager.createXxx()
    ↓
Store.create() → Generate ID
    ↓
FileSystem.writeFile()
    ↓
Obsidian Vault API
```

### 3.2 渲染看板

```
Markdown Render
    ↓
pm-kanban Code Block Processor
    ↓
KanbanBoard.render()
    ↓
EntityManager.listFeatures()
    ↓
CardRegistry.findRenderer() → FeatureCard.render()
    ↓
HTMLElement with click handler
```

### 3.3 渲染独立卡片

```
Markdown Render
    ↓
pm-card Code Block Processor
    ↓
SingleCardRenderer.render()
    ↓
EntityManager.findById()
    ↓
CardRegistry.findRenderer() → XxxCard.render(entity, onClick)
    ↓
Clickable HTMLElement
```

## 4. 数据流

### 4.1 单向数据流

```
State (Markdown Files)
    ↓
FileSystem.readFile() → EntityManager
    ↓
UI Layer (KanbanBoard / SingleCardRenderer)
    ↓
User Interaction (Click Card)
    ↓
Open File (Obsidian API)
```

### 4.2 卡片点击跳转

```
User Click Card
    ↓
onClick callback
    ↓
EntityManager.getEntityPath(id)
    ↓
Obsidian Workspace.openFile()
    ↓
Navigate to Markdown File
```

## 5. 关键技术决策

### 5.1 架构模式

- [x] **双层架构** (Core + UI)
  - Core: 数据管理，与 Obsidian API 交互
  - UI: 展示层，通过 EntityManager 获取数据

**决策说明**: 职责分离，便于测试和扩展。

### 5.2 卡片组件化

- [x] **CardRegistry 模式**
  - 每个实体类型对应一个 Card 类
  - 动态查找匹配的 Card 渲染器
  - 支持扩展新的卡片类型

**决策说明**: 解耦实体数据与展示逻辑，支持独立卡片功能。

### 5.3 视图实现

- [x] 原生 DOM + CSS（MVP 首选，减少依赖）
- [ ] Svelte 组件（后续迭代考虑）
- [ ] React 组件

**决策说明**: MVP 阶段使用原生 DOM，直接操作 Obsidian 的 Markdown 渲染。

### 5.4 索引策略

- [x] 内存缓存 + 文件监听更新
- [ ] 实时扫描文件系统
- [ ] 持久化索引文件

**决策说明**: 遵循"文件即真相"原则，每次从文件读取最新数据。

## 6. 扩展指南

### 6.1 添加新实体类型

1. 在 `types/` 添加类型定义
2. 在 `core/stores/` 创建 Store 类
3. 在 `EntityManager` 注册新 Store
4. 在 `ui/cards/` 创建 Card 类
5. 在 `CardRegistry.createDefault()` 注册新 Card

### 6.2 自定义卡片样式

```typescript
// 继承现有卡片或实现 CardComponent
export class MyCustomCard implements CardComponent {
  id = 'custom';
  
  matches(entity: unknown): boolean {
    // 判断是否匹配
  }
  
  render(entity: unknown, onClick?: () => void): HTMLElement {
    // 返回自定义 DOM
  }
}

// 注册到 CardRegistry
registry.register(new MyCustomCard());
```

## 7. 性能考虑

| 场景 | 策略 |
|------|------|
| 大量文件加载 | 按需读取，不预加载 |
| 频繁文件变更 | 依赖 Obsidian 缓存 |
| 关系查询 | 通过 ID 弱引用查找 |
| 视图渲染 | 原生 DOM，无框架开销 |
| 卡片点击 | 异步获取路径，无阻塞 |
