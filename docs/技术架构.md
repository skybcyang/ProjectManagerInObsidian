### 2.2 三层存储架构

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 1: 内存缓存 (EntityCache)                              │
│ - Map<string, Version> versionCache                         │
│ - Map<string, Project> projectCache                         │
│ - Map<string, Feature> featureCache                         │
│ - 文件监听自动更新 (create/modify/delete/rename)            │
└─────────────────────────────────────────────────────────────┘
                              ↕
┌─────────────────────────────────────────────────────────────┐
│ Layer 2: Obsidian 元数据缓存 (metadataCache)                 │
│ - 自动解析 frontmatter                                      │
│ - 监听文件变更事件                                          │
└─────────────────────────────────────────────────────────────┘
                              ↕
┌─────────────────────────────────────────────────────────────┐
│ Layer 3: 文件系统 (Vault)                                    │
│ ProjectManager/                                             │
│ ├── Versions/                                               │
│ │   └── {版本名}.md                                         │
│ ├── Projects/                                               │
│ │   └── {版本名}-{项目名}.md                                │
│ └── Features/                                               │
│     └── {版本名}-{项目名}-{特性名}.md                       │
└─────────────────────────────────────────────────────────────┘
```

## 3. 核心机制

### 3.1 文件命名规则

| 实体 | 文件名格式 | 示例 |
|------|-----------|------|
| 版本 | `{版本名}.md` | `V1.0 Initial Release.md` |
| 项目 | `{版本名}-{项目名}.md` | `V1.0 Initial Release-用户系统.md` |
| 特性 | `{版本名}-{项目名}-{特性名}.md` | `V1.0 Initial Release-用户系统-登录功能.md` |

**文件名生成逻辑：**
1. 版本：直接使用版本 `name`
2. 项目：查找版本名称 + 项目 `name`
3. 特性：查找版本名称 + 项目名称 + 特性 `name`
4. 非法字符自动清理（`\ / : * ? " < > |`）
5. 长度限制：100字符

### 3.2 缓存同步机制

```
用户删除文件夹
    ↓
Obsidian 触发 'delete' 事件
    ↓
EntityCache.handleFileDelete(file)
    ↓
通过文件名匹配查找缓存项
    ↓
从对应 Map 中 delete(id)
    ↓
缓存与文件系统保持一致
```

### 3.3 筛选栏布局

```
┌─────────────────────────────────────────────────────────────┐
│ [版本 ▼] [项目 ▼] [特性 ▼] [状态 ▼] [优先级 ▼] [负责人 ▼] [↺ 重置] │
└─────────────────────────────────────────────────────────────┘
```

- **6个筛选下拉框**：紧凑横向排列，使用 placeholder 显示类型
- **重置按钮**：一键清空所有筛选条件
- **级联更新**：选择版本 → 更新项目列表 → 更新特性列表

## 4. 视图系统

### 4.1 支持的视图模式

| 视图 | 模式值 | 渲染器 | 主要用途 |
|------|--------|--------|----------|
| 看板视图 | `kanban` | KanbanRenderer | 类 Trello 拖拽看板 |
| 列表视图 | `list` | ListRenderer | 表格形式，支持行内编辑 |
| 网格视图 | `grid` | GridRenderer | 卡片网格布局 |
| 级联视图 | `cascade` | CascadeRenderer | 版本→项目→特性层级 |
| 时间线视图 | `timeline` | TimelineRenderer | 水平/垂直时间轴 |
| 日历视图 | `calendar` | CalendarRenderer | 月历视图 |

### 4.2 统一卡片组件 (EntityCard)

**可配置字段：**
- `showPriority`: 优先级标记条
- `showStatus`: 状态徽章
- `showOwner`: 负责人
- `showDueDate`: 截止日期
- `showProgress`: 进度条
- `showTags`: 标签
- `smallTitle`: 小标题模式

**字段配置（`cardFields`）：**
```yaml
cardFields:
  required: [name, priority]      # 始终显示
  optional: [status, owner, progress, tags, description, actions]  # 用户可选
```

### 4.3 列表视图列配置

```yaml
mode: list
entityType: feature
listColumns:
  - name
  - status
  - priority
  - owner
  - dueDate
  - progress
```

## 6. 性能优化

| 场景 | 策略 |
|------|------|
| 大量文件加载 | 内存缓存 + 懒加载 |
| 频繁文件变更 | Obsidian 事件监听，增量更新 |
| 关系查询 | 通过 ID 弱引用，实时查找 |
| 视图渲染 | 原生 DOM，无框架开销 |
| 筛选过滤 | 内存中过滤，不重复读取文件 |

## 7. 扩展指南

### 7.1 添加新视图模式

1. 在 `view-engine/renderers/` 创建新渲染器类
2. 继承 `BaseRenderer`
3. 实现 `render(container: HTMLElement)` 方法
4. 在 `ViewEngine.renderContent()` 中注册新视图

### 7.2 自定义模板

1. 在设置面板中启用自定义模板
2. 编辑 `ProjectManager/.templates/{type}.md`
3. 使用模板变量：`{{name}}`, `{{status}}`, `{{#if}}...{{/if}}`
