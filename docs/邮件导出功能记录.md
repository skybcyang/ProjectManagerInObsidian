# 邮件导出功能记录

## 当前状态（2026-04-14）

### 已实现

- **`.eml` 文件生成** - 通过 `src/utils/emlGenerator.ts` 生成符合 MIME 规范的 `multipart/alternative` 格式邮件，包含 `text/plain` 和 `text/html` 两部分。
- **页面渲染结果捕获** - `src/utils/pageCapture.ts` 支持从 Obsidian Reading view 捕获当前页面的实际渲染 DOM，清理交互元素后导出为邮件 HTML。
- **全局事件委托** - `src/main.ts` 中注册了 `document` 级别的 click 事件委托，确保 Reading view 下 `pm-btn` 按钮可点击。
- **样式内联与嵌入** - 捕获时自动嵌入插件 `styles.css` 的全部内容，并快照当前 CSS 变量（如 `--pm-primary`、`--pm-bg` 等），确保邮件客户端能看到颜色和基础布局。
- **结构化总结备选** - `EmailSummaryService` 仍保留模板-based 的 `buildEmailForActiveFile()` 方法作为备选。
- **弹窗双模式** - `ExportEmailModal` 提供两种导出方式：
  - "导出当前页面渲染邮件"（主要按钮）
  - "导出结构化总结邮件"（次要按钮）

### 已知问题

- **布局在 Outlook 中显示不佳** - 虽然样式已嵌入，但邮件客户端（尤其是 Outlook）对 `display: flex`、复杂定位、虚拟滚动容器的支持有限，导致看板/表格/网格等视图出现"歪瓜裂枣"的排版问题。
- **Obsidian 内部 UI 残留** - 部分 Obsidian 装饰元素（如折叠图标、frontmatter 代码块容器等）虽然已清理，但相关空容器或间距仍可能影响邮件布局。
- **Dataview 表格样式依赖 Obsidian 主题** - 邮件中 Dataview 表格的颜色和边框仍部分依赖当前 Obsidian 主题变量，在不同邮件客户端中表现不一致。

## 后续改进想法

### 核心思路

当前直接捕获整页 DOM 的方式在邮件客户端中兼容性差，需要为每种视图模式提供**更适合邮件 HTML 的渲染方案**。

### 需求细节

---start---
需要显示的内容用 `---start---` 和 `---end---` 进行标记。

1. **Dataview 正常渲染**
   - Dataview 表格在邮件中应保持完整的边框、表头背景、对齐方式。
   - 不显示原始代码块或配置文本。

2. **视图模式各自提供邮件渲染方式**
   - `kanban` 看板模式：在邮件中转换为适合窄屏的表格或列表，保留卡片颜色、状态分组、负责人信息。
   - `list` 列表模式：直接渲染为 HTML `<table>`，保留行内编辑不可操作但样式完整。
   - `grid` 网格模式：转换为单列卡片流或简化网格，避免邮件客户端 flex/grid 布局塌陷。
   - `cascade` 级联模式：保持层级缩进，用表格或嵌套列表展示版本→项目→特性关系。
   - `timeline` / `timeview` / `burndown` / `workload`：提供简化静态图表（SVG 或简化表格）替代复杂布局。

3. **全屏截图兜底方案**
   - 当某种视图模式无法优雅地转换为邮件 HTML 时，允许该模式在后台全屏渲染后生成截图（如通过 `html2canvas` 或 `dom-to-image`），将截图以 `<img>` 形式嵌入邮件。
   - 截图方案仅作为特定视图模式的 fallback，不替代常规 HTML 导出。

4. **内容标记规范**
   - 用户在笔记中可用 `---start---` 和 `---end---` 标记需要纳入邮件总结的核心内容段落。
   - 导出时优先提取标记区域内的文本/表格/列表，未标记区域作为补充。

5. **移除所有 Obsidian UI 噪音**
   - 彻底清理 frontmatter 代码块、折叠指示器、属性面板、面包屑、编辑按钮等非内容元素。
   - 确保邮件正文只包含：标题、标记内容、Dataview 结果、pm-view 渲染结果。

6. **移动端邮件兼容**
   - 生成的 HTML 应使用 `<table>` 布局为主，避免依赖 `display: flex`。
   - 图片使用 `max-width: 100%`。
   - 内联所有关键样式，不依赖外部 CSS。
---end---

### 技术方向

- 为 `BaseRenderer` 增加可选的 `renderForEmail(container: HTMLElement): Promise<string>` 接口。
- 每种视图模式逐步实现邮件友好的 HTML 生成逻辑。
- 调研 `html2canvas` 或现代浏览器的 `captureViewport` API 作为截图兜底。
- 在 `pageCapture.ts` 中增加 `---start---` / `---end---` 标记解析逻辑。
