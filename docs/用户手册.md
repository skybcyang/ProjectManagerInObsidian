# 用户手册

> **适用版本**: v0.8.4
>
> 面向普通用户的使用指南，帮助你快速上手 Project Manager 插件。

---

## 1. 安装与启用

### 1.1 从 GitHub Release 安装

1. 打开项目 [Releases 页面](https://github.com/your-username/obsidian-project-manager/releases)。
2. 下载最新版本压缩包：`obsidian-project-manager-v0.8.4.zip`。
3. 解压到 Obsidian Vault 的 `.obsidian/plugins/` 目录下，得到 `obsidian-project-manager` 文件夹。
4. 重启 Obsidian。
5. 进入 **设置 → 社区插件 → 已安装插件**，启用 **Project Manager**。

### 1.2 手动构建安装

```bash
git clone https://github.com/your-username/obsidian-project-manager.git
cd obsidian-project-manager
npm install
npm run build
```

将生成的 `main.js`、`manifest.json`、`styles.css` 放入 `.obsidian/plugins/obsidian-project-manager/`。

## 2. 快速开始

启用插件后，插件会自动在 Vault 根目录创建以下结构：

```
ProjectManager/
├── Versions/        # 版本
├── Projects/        # 项目
├── Requirements/    # 需求
├── Features/        # 特性
└── 总览.md          # 总览入口
```

### 2.1 打开总览页

点击左侧功能区 **Project Manager** 图标，或打开 `ProjectManager/总览.md`。

总览页提供：
- 当前进行中的版本/项目/需求/特性概览
- 逾期事项提醒
- 快速创建按钮（版本、项目、需求、特性）
- 常用视图入口

## 3. 创建实体

Project Manager 采用 **三层结构化管理 + 需求单独管理** 的模型：

- **版本（Version）**：最高层，对应一次发布、迭代或季度目标。
- **项目（Project）**：从属于版本，对应一个业务或交付单元。
- **特性（Feature）**：从属于项目，对应可交付的功能点。
- **需求（Requirement）**：独立管理，可关联到版本/项目/特性，但不纳入级联层级。

### 3.1 创建版本

1. 在总览页点击 **创建版本**，或执行命令 `Project Manager: 创建版本`。
2. 填写名称、状态、负责人、起止日期、标签。
3. 确认后插件生成 `ProjectManager/Versions/{版本名}.md`。

### 3.2 创建项目

1. 点击 **创建项目**，选择所属版本。
2. 填写名称、优先级、状态、负责人等。
3. 项目文件保存到 `ProjectManager/Projects/{项目名}.md`。

> 项目是版本的子集，创建时必须指定版本。

### 3.3 创建需求

1. 点击 **创建需求**。
2. 填写名称、优先级、状态等。
3. 可选关联：
   - **版本**：需求跟随该版本下发。
   - **项目**：需求归属的项目。
   - **特性**：需求对应的特性。
4. 需求文件保存到 `ProjectManager/Requirements/`。

> 需求**不强制**关联项目/特性，适合早期未拆分到项目的需求。

### 3.4 创建特性

1. 点击 **创建特性**，选择版本和项目。
2. 填写名称、优先级、状态、负责人、进度等。
3. 特性文件保存到 `ProjectManager/Features/`。

> 特性必须属于某个版本和项目。多个需求可对应同一个特性。

## 4. 管理视图

视图通过 `pm-view` 代码块定义，可在任意 Markdown 文件中插入。

### 4.1 创建视图

1. 在总览页或任意笔记中输入：

   ````markdown
   ```pm-view
   mode: kanban
   entityType: requirement
   groupBy: status
   title: 需求看板
   ```
   ````

2. 切换为阅读模式，即可看到渲染后的看板。

### 4.2 常用视图示例

**需求看板**

```yaml
mode: kanban
entityType: requirement
groupBy: status
cardFields:
  required: [name, priority]
  optional: [status, owner, progress, endDate]
```

**级联视图（版本→项目→特性）**

```yaml
mode: cascade
entityType: feature
groupBy: status
options:
  expanded: true
  maxProjects: 10
  maxFeaturesPerProject: 5
```

> 需求不纳入级联层级，请在看板中单独展示。

**时间视图**

```yaml
mode: timeview
entityType: feature
timeViewMode: month
timeGroupBy: project
```

### 4.3 筛选数据

```yaml
# 只看指定版本
version: ver-xxx

# 只看多个项目
projects: [proj-xxx, proj-yyy]

# 按状态筛选
status: in-progress

# 按负责人筛选
owner: 张三

# 按标签筛选
tag: 重要
```

### 4.4 排序与限制

```yaml
sortBy: endDate
sortOrder: desc
limit: 20
```

## 5. 模板定制

进入 **设置 → Project Manager → 模板**，可修改默认模板。

### 5.1 默认模板类型

- 总览模板
- 版本模板
- 项目模板
- 需求模板
- 特性模板

### 5.2 常用变量

| 变量 | 说明 |
|------|------|
| `{{name}}` | 实体名称 |
| `{{id}}` | 实体 ID |
| `{{status}}` | 状态 |
| `{{priority}}` | 优先级 |
| `{{priorityEmoji}}` | 优先级表情 |
| `{{owner}}` | 负责人 |
| `{{startDate}}` | 开始日期 |
| `{{endDate}}` | 结束日期 |
| `{{tags}}` | 标签 |
| `{{progress}}` | 进度 |

需求模板特有变量：`{{versionId}}`、`{{projectId}}`、`{{featureId}}`。

### 5.3 自定义示例

```markdown
# {{name}}

**状态**: {{status}} {{statusEmoji}}
**优先级**: {{priority}} {{priorityEmoji}}
**负责人**: {{owner}}
**起止日期**: {{startDate}} ~ {{endDate}}
**标签**: {{#each tags}}#{{this}} {{/each}}

## 描述

{{description}}

## 关联

- 版本: {{versionId}}
- 项目: {{projectId}}
- 特性: {{featureId}}
```

## 6. 插件设置

打开 **设置 → Project Manager**：

| 设置项 | 说明 |
|--------|------|
| 数据目录 | 实体笔记存放的根目录，默认 `ProjectManager` |
| 视图刷新间隔 | 看板/级联/时间视图自动刷新间隔（秒） |
| Dataview 集成 | 启用后优先使用 Dataview 查询加速 |
| 默认模板 | 修改各类型实体的创建模板 |

## 7. 常见问题

### Q1: 创建需求时能否不关联项目？

可以。需求可独立存在，仅关联版本；也可后续编辑再补充项目/特性。

### Q2: 删除版本会删除哪些内容？

删除版本时，插件会先级联删除该版本下的**需求**，再删除该版本下的**项目**（及其关联特性）。

### Q3: 需求为什么不出现在级联视图里？

级联视图固定为 `版本 → 项目 → 特性` 三层。需求是独立实体，请使用看板视图展示。

### Q4: 数据会丢失吗？

所有实体都是普通 Markdown 文件，存储在 Vault 内，可正常参与 Obsidian 同步和 Git 版本控制。

### Q5: 如何批量修改实体属性？

目前支持在对应 Markdown 文件的 YAML frontmatter 中手动修改属性。后续版本将支持通过看板拖拽修改状态。
